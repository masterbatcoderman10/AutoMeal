## Summary

Phase 04.2 should be implemented as an additive LLM turn layer over the existing interview persistence and finalization surfaces, not as a rewrite of session storage, grounding handoff, or final writes. [VERIFIED: codebase grep] The repo already has the right ownership boundaries for this: grouped reasoning persists on `MealLog.reasoning_state_json`, durable interview state persists on `InterviewSession.current_prompt_payload` plus `InterviewMessage`, and both auto-confirm and interview-confirm paths already converge on `apply_final_meal_resolution()`. [VERIFIED: codebase grep]

The concrete failure is inside the current continuation logic. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md] `interview_text()` loads the most recent active session for the chat, `parse_interview_text()` parses the latest reply in isolation, `complete_target_question()` advances a fixed roadmap step-by-step, and `prepare_interview_session()` only seeds unresolved targets, not clear groups that still need approval. [VERIFIED: codebase grep] That shape explains the observed `What should I call It's bottle gourd?` failure and also leaves the stale-session-stealing risk partially unaddressed for free-text replies. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md][VERIFIED: codebase grep]

The plan-ready design is to keep DB state authoritative, send that state plus bounded durable transcript history into an OpenRouter Chat Completions call with strict JSON Schema output, and accept only three model actions: `continue_interview`, `need_clarification`, or `ready_to_confirm`. [CITED: https://openrouter.ai/docs/guides/features/structured-outputs][CITED: https://platform.openai.com/docs/guides/structured-outputs?api-mode=chat][VERIFIED: codebase grep] `ready_to_confirm` must produce normalized confirmation items that include approval/correction status for both unclear and clear groups, and those items must flow through `finalize_confirmed_interview()` unchanged except for validation. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md][VERIFIED: codebase grep]

**Primary recommendation:** Keep OpenRouter Chat Completions plus Langfuse as-is, add a strict interview-turn response contract and message-scoped reply routing, and route every `ready_to_confirm` result back through `finalize_confirmed_interview()` and `apply_final_meal_resolution()` rather than letting the LLM write anything directly. [VERIFIED: codebase grep][CITED: https://openrouter.ai/docs/quickstart][CITED: https://openrouter.ai/docs/guides/features/structured-outputs][CITED: https://langfuse.com/docs/integrations/openai?trk=public_post_comment-text]

## Current Implementation Diagnosis

1. `prepare_interview_session()` currently seeds `pending_targets` only from groups that `_group_needs_interview()` considers unresolved, so clear/high-confidence groups are omitted from the first question payload even though 04.2 explicitly requires approval candidates in the same turn. [VERIFIED: codebase grep][CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md]
2. `interview_text()` currently calls `_load_active_interview(session, chat_id=chat_id)` with no meal or message scoping, and `_load_active_interview()` simply returns the most recently updated active session for the pinned chat. [VERIFIED: codebase grep] This is the exact seam that can let stale sessions steal free-text replies when multiple interviews are active. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md][VERIFIED: codebase grep]
3. `InterviewSession.last_bot_message_id` and `InterviewMessage.message_id` already exist in the schema, but current kickoff and reply flows never populate them from sent Telegram messages. [VERIFIED: codebase grep] That means the repo already has a persistence slot for prompt-scoped reply routing, and 04.2 can use it without adding a new table. [VERIFIED: codebase grep]
4. `parse_interview_text()` strips prefixes like `it's` and then maps the reply directly into the current roadmap step, while `complete_target_question()` advances the deterministic roadmap regardless of richer meal context. [VERIFIED: codebase grep] This is why a reply like `It's bottle gourd` becomes a literal name instead of a contextual correction to `egg curry`. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md][VERIFIED: codebase grep]
5. `answer_to_confirmation_item()` and `confirmation_items_from_state()` preserve group and segment identity, but they do not currently capture explicit approval/correction status for clear groups versus unresolved groups. [VERIFIED: codebase grep] 04.2 needs those statuses in `ready_to_confirm` output because the phase contract requires approval or correction for every group, not only a final flat name list. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md]
6. `finalize_confirmed_interview()` already preserves the authoritative write path by turning confirmation items into `FinalSegmentResolution` objects and then calling `apply_final_meal_resolution()` or the existing grounding handoff. [VERIFIED: codebase grep] 04.2 must treat this as locked infrastructure and only change the shape and validation of the confirmation items fed into it. [VERIFIED: codebase grep][CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md]
7. `OpenRouterClient.chat_completion()` already exposes exactly the request surface this phase needs: `messages`, `response_format`, `tools`, `extra_body`, and `max_tokens`, and it is already backed by `langfuse.openai.AsyncOpenAI`. [VERIFIED: codebase grep][CITED: https://openrouter.ai/docs/quickstart][CITED: https://langfuse.com/docs/integrations/openai?trk=public_post_comment-text]
8. `app/config.py` has explicit reasoning model keys but no explicit interview model or fallback keys yet. [VERIFIED: codebase grep] Adding those keys is required by the 04.2 success criteria and should happen in config, not as hard-coded literals in the turn manager. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/ROADMAP.md][VERIFIED: codebase grep]

### Anti-Patterns to Avoid

- **Raw-text-as-state:** Do not let the transcript become the only source of truth for names, source type, or portion; keep those fields in structured session state. [VERIFIED: codebase grep]

## Common Pitfalls

### Pitfall 1: Stale Session Steals the Reply
**What goes wrong:** A free-text Telegram reply attaches to the wrong active meal interview because the handler only asks for the newest active session on the pinned chat. [VERIFIED: codebase grep]  
**Why it happens:** `_load_active_interview()` in `bot/handlers.py` orders by `updated_at desc` and does not use prompt message ids, while `last_bot_message_id` is currently unused. [VERIFIED: codebase grep]  
**How to avoid:** Persist the sent prompt message id, prefer prompt-scoped resolution for free-text replies, and deactivate superseded sessions when a newer session becomes authoritative. [VERIFIED: codebase grep][ASSUMED]  
**Warning signs:** A test can create two active interviews for the same chat and the reply still routes solely by newest timestamp. [VERIFIED: codebase grep]

### Pitfall 2: Clear Approval Groups Disappear From the Interview Context
**What goes wrong:** The LLM can only talk about unresolved items because the session state contains only interview-needed groups, so clear `pita bread` or `chicken curry` approvals never reach the user in the same turn. [VERIFIED: codebase grep][CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md]  
**Why it happens:** `_pending_targets_from_food_groups()` filters only interview-needed groups today. [VERIFIED: codebase grep]  
**How to avoid:** Split state into unresolved targets and approval candidates, and require `ready_to_confirm` to return statuses for both sets. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md][ASSUMED]  
**Warning signs:** First-turn prompts mention only the unclear curry detail and omit already-clear items that the acceptance examples expect to be approved or corrected. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md]

### Pitfall 3: Model Output Bypasses the Authoritative Write Path
**What goes wrong:** The LLM starts deciding what gets persisted and how, and the repo silently forks from the already-working writer path. [VERIFIED: codebase grep]  
**Why it happens:** It is tempting to treat `ready_to_confirm` as a final write command rather than as validated input to `finalize_confirmed_interview()`. [VERIFIED: codebase grep]  
**How to avoid:** Treat the model output as untrusted structured data; validate it, then hand it to the existing confirmation finalizer. [VERIFIED: codebase grep][CITED: https://openrouter.ai/docs/guides/features/structured-outputs]  
**Warning signs:** New code writes `DiaryEntry` or `FoodVisual` rows anywhere outside `apply_final_meal_resolution()` or the current correction path. [VERIFIED: codebase grep]

### Pitfall 4: Literal Answer Echo Instead of Contextual Composition
**What goes wrong:** The model or a fallback parser treats `bottle gourd` as the full food name instead of resolving the hidden detail inside `egg curry`. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md][ASSUMED]  
**Why it happens:** The turn contract does not require normalized final names and the state object does not make the missing-detail relationship explicit enough. [VERIFIED: codebase grep][ASSUMED]  
**How to avoid:** Include the prior proposed name, the missing evidence field, and the current target label in the LLM state, and require `ready_to_confirm.confirmation_items[*].name` to be the final normalized name, not the raw answer fragment. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md][ASSUMED]  
**Warning signs:** A regression test with input `It's bottle gourd` still produces either `It's bottle gourd` or `bottle gourd` as the confirmed item name. [CITED: /Users/mali/Documents/Projects/MealTracker/.planning/phases/04.2-llm-threaded-interview-orchestration/04.2-CONTEXT.md][ASSUMED]

### Pitfall 5: Silent Structured-Output Drift
**What goes wrong:** The model returns malformed JSON or missing fields, and the handler falls back to best-effort string parsing that reintroduces the old deterministic bug class. [CITED: https://openrouter.ai/docs/guides/features/structured-outputs][VERIFIED: codebase grep]  
**Why it happens:** Structured outputs still require a valid schema and a model that supports `response_format: json_schema`, and invalid model output can happen if validation is weakened. [CITED: https://openrouter.ai/docs/guides/features/structured-outputs][CITED: https://platform.openai.com/docs/guides/structured-outputs?api-mode=chat]  
**How to avoid:** Use strict JSON Schema, Pydantic validation, a bounded repair retry, and explicit failure behavior instead of raw-text fallback. [VERIFIED: codebase grep][CITED: https://openrouter.ai/docs/guides/features/structured-outputs]  
**Warning signs:** New code branches back into `parse_interview_text()` on invalid model output rather than failing closed or retrying once through a repair path. [VERIFIED: codebase grep]
