### Gaps Summary

`CR-01` is a true blocker for the Phase 4.2 goal. The phase claims grouped `ready_to_confirm` items can flow through the existing final write-back or post-interview grounding path, but the shipped contract only preserves one `segment_id` per confirmation group while the grounding worker rebuilds candidates per segment. For grouped `PACKAGED` or `RESTAURANT` answers, sibling segments are lost and `poll_post_interview_grounding()` moves the meal to `RETRY_PENDING` instead of letting the authoritative Phase 4.1 writer finish the meal.

Gap-closure plan recommendations:

1. Extend `ConfirmationItem` to carry grouped segment membership, not just one `segment_id`.
2. Preserve that grouped membership through `ready_to_confirm` persistence and `build_grounding_reasoning_state()`.
3. Rebuild post-interview grounding candidates for every `segment_id` in the group, not just the primary segment.
4. Add a regression test in `tests/test_bot_contract.py` that sends a multi-segment grouped `PACKAGED` or `RESTAURANT` confirmation through `poll_post_interview_grounding()` and asserts no segment lands in `grounding_missing_segments`.
5. Fix `scripts/assert_phase_04_2_preflight.py` so it supports the project’s allowed Python 3.13 runtime or explicitly selects Python 3.12 before venv creation.
