# Phase 4.1: Grouped Reasoning & Human Interview Correction - Context

**Gathered:** 2026-05-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 4.1 fixes a Phase 4 UAT failure found during live testing with `sample_images/IMG_4646.HEIC`. Phase 4 successfully sends whole-meal and segment images into the reasoning model and captures Langfuse traces, but its reasoning contract still exposes one meal-level `top_3`. In the observed trace, the top three records were separate foods in the same meal (`Chicken Curry With Pita Bread`, `Egg and Zucchini Curry with Whole Boiled Eggs`, `Whole Wheat Pita Bread`) instead of competing candidates for one item. The gate compared unrelated foods, routed to interview, and the bot asked a raw segment question that sounded robotic and developer-facing.

This corrective phase must keep the Phase 4 one-call multimodal reasoning shape, but change the output and downstream interview target model so the model groups distinct foods/components first, ranks candidates per group, and asks one targeted human question only for unresolved groups.

This phase does not implement Phase 5 grounding tools, nutrition derivation expansion, new slash commands, a frontend, or broad bot redesign.
</domain>

<decisions>
## Locked Decisions

### Reasoning Contract
- **D-01:** Reasoning remains one meal-level multimodal call over the original meal image, indexed segment crops, detector labels, bounding boxes, and per-segment vector candidates.
- **D-02:** The primary reasoning output must add grouped food records, tentatively named `food_groups`, where each group represents one distinct food/component or one composite line item decision.
- **D-03:** Each food group must include stable `segment_ids`, a user-facing `label`, group action/state, visible evidence, missing evidence, gate reason, and exactly three candidate identifications ranked within that group.
- **D-04:** Candidate margin and top-1/top-2 comparison must happen inside a food group only. Unrelated groups such as chicken curry, egg curry, and pita bread must not be compared as if they are alternatives.
- **D-05:** Keep meal-level summary state for final routing, but do not make root-level `top_3` the only reasoning surface. Root state may aggregate group states, but the group records are the source of truth for interview targets.
- **D-06:** Preserve auditability on `MealSegment.ai_reasoning`, but stop copying the identical whole-meal top-3 onto every segment. Segment audit should either point to its owning group or include a compact group-specific snapshot.

### Interview Targeting
- **D-07:** Telegram interview sessions target unresolved food groups, not raw detector segments.
- **D-08:** Duplicate or overlapping detector labels must be collapsed before prompting the user. The observed pending targets `egg and vegetable curry`, `egg and zucchini curry`, `pita bread`, `chicken curry`, `bread`, and `chicken curry with pita bread` should become a smaller set of meaningful food groups.
- **D-09:** Ask identity/detail before quantity. If the only high-impact uncertainty is the vegetable inside an egg curry, ask that one concrete question.
- **D-10:** The interview state must stay DB-owned and recoverable through existing `InterviewSession.current_prompt_payload` and `InterviewMessage` patterns.

### User-Facing Copy
- **D-11:** User-facing Telegram copy must be brief, human, and answerable from memory. Avoid internal phrases like `nutrition-relevant detail`, `preparation detail that changes nutrition`, `candidate margin`, `segment`, or `confidence`.
- **D-12:** A good curry question is: `I can see the egg curry, but I can't tell which vegetable is in it. What should I call it? For example: egg curry with bottle gourd, egg curry with zucchini, or the name you normally use.`
- **D-13:** The bot may mention uncertainty naturally, but should not sound like a schema validator or require the user to know how the pipeline works.

### UAT Evidence
- **D-14:** Use `sample_images/IMG_4646.HEIC` as the reference UAT sample for this phase.
- **D-15:** Verification must include a fresh docker-compose run or targeted local test proving the sample produces grouped reasoning and a human group-level interview prompt.
- **D-16:** Langfuse traces must continue to include the exact model input/output and images/media handles for the reasoning call.

### Scope Fence
- **D-17:** Do not add SearXNG or Firecrawl tool loops in Phase 4.1.
- **D-18:** Do not expand nutrition derivation beyond what existing Phase 4 final write paths already support.
- **D-19:** Do not rewrite the full Telegram command surface. Touch interview prompt construction only where needed for grouped unresolved targets.
- **D-20:** Maintain OpenRouter-only LLM access and strict structured outputs.
</decisions>

<specifics>
## Observed Failure From UAT

Meal `8ece0caf-e33e-46a7-86b0-3aaed4d12e74` produced a stored root `top_3` of:

1. `Chicken Curry With Pita Bread` - identity confidence `0.92`
2. `Egg and Zucchini Curry with Whole Boiled Eggs` - identity confidence `0.89`
3. `Whole Wheat Pita Bread` - identity confidence `0.95`

The persisted `gate_reason` was `candidate margin 0.030 is too narrow`, but the margin compared unrelated foods. The same whole-meal top-3 was copied into every `segment_reasoning` record. The interview state then created pending targets from raw segment labels, starting with `egg and vegetable curry`, and sent:

`I detected egg and vegetable curry. What exactly should I log for it? Include the main food name and any key ingredient or preparation detail that changes nutrition...`

The user rejected this because it sounds robotic, assumes developer knowledge, and fails to ask the actual useful question: which vegetable is inside the egg curry.

## Expected Shape

The desired mental model is:

- First isolate hard distinct foods/groups from whole meal plus segments.
- For each food/group, produce its own top three candidates and confidence/evidence.
- Gate and ask questions per group.
- Aggregate group states into meal state.

Example target groups for the sample:

- Egg curry group: segments covering the egg curry bowl; unresolved only if vegetable identity is unclear.
- Chicken curry group: segments covering chicken curry/drumstick; likely auto-confirm if evidence is clear.
- Pita/flatbread group: bread segments collapsed together; likely auto-confirm if evidence is clear.
</specifics>
