# Phase 04.3 - Security

Per-phase security contract for deterministic clarification schema and interview UI work.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| OpenRouter reasoning output -> persisted grouped reasoning state | Untrusted model JSON crosses into the app and must be normalized before any gate or Telegram flow can consume it. | LLM JSON, candidate labels, grouped reasoning, clarification metadata |
| grouped reasoning state -> clarification batch | Candidate ranking and source-origin rules determine user-facing questions and must not silently fall back to root `top_3`. | Group-owned candidate rankings and deterministic clarification questions |
| persisted clarification state -> Telegram prompt | Stored reasoning questions become user-facing prompts and must remain deterministic across retries and restarts. | DB-backed question metadata, prompt payloads, callback data |
| Telegram callback/text reply -> stored answer state | User input arrives through callback data or free text and must be validated against DB-backed question identity before any state mutation. | Callback payloads, Telegram message IDs, text answers |
| completed clarification state -> resolver input | Structured answers become model input and must be complete before the resolver runs. | `answers_by_question_id`, transcript, grouped reasoning state |
| resolver output -> authoritative DB write path | The resolver can influence FoodItem, DiaryEntry, and FoodVisual writes and must be tightly bounded to confirmation output only. | Resolver confirmation items, finalization metadata, trace payloads |
