## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| vector candidates -> LLM reasoning | Persisted similarity signals and visual evidence cross into a model call that must not overwrite business rules. |
| model output -> meal completion | Structured output becomes durable diary history only after deterministic gate checks and validation. |
| parallel segment tasks -> final transaction | Concurrent segment preparation must not create duplicate writes or partial completion races. |

## STRIDE Threat Register

High-severity gate: none in this plan. Every listed threat is medium severity and non-blocking once the listed mitigation is implemented.

| Threat ID | Category | Component | Severity | Blocking | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|----------|-------------|-----------------|
| T-04-05 | Tampering | `app/services/reasoning_schema.py` | medium | no | mitigate | Keep strict JSON schema, open-string `action`, and explicit unknown-action routing to `NEEDS_SCHEMA_REVIEW` per D-17 and D-18. |
| T-04-06 | Tampering | `app/services/reasoning_service.py` | medium | no | mitigate | Gate auto-confirm using similarity, top-1 vs top-2 margin, missing evidence, and nutrition-impact checks rather than self-confidence alone per D-23 and REASON-03. |
| T-04-07 | Repudiation | `bot/polling.py` | medium | no | mitigate | Persist `match_candidates_json`, `MealSegment.ai_reasoning`, and meal-level reasoning state before any final write so retries can resume from artifacts. |
| T-04-08 | Denial of Service | semaphore fan-out | medium | no | mitigate | Use configurable bounded concurrency and fail closed when any segment exhausts its retry budget instead of letting one stuck task block sibling progress forever. |
| T-04-SC | Tampering | tracing wrapper and model client | medium | no | mitigate | Propagate trace IDs when available but allow tracing failure to degrade to no-op without changing gate or write behavior. |
</threat_model>
