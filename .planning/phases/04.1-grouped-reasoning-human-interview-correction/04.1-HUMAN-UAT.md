```bash
rtk docker compose exec -T postgres psql -U mealttracker -d mealttracker -c "
TRUNCATE TABLE
  correction_events,
  interview_messages,
  interview_sessions,
  diary_entries,
  meal_segments,
  meal_logs,
  food_visuals,
  food_items
RESTART IDENTITY CASCADE;
"
```

Expected result:

- `food_items`, `food_visuals`, `diary_entries`, and `meal_logs` are empty
- no open `interview_sessions` remain

## Human UAT Checklist

### Upload 1

- Action: send the first real meal photo through the same ingest path the iOS Shortcut uses
- Expectation:
  - meal reaches reasoning or interview from an empty DB
  - any created FoodItem name comes from grouped reasoning or your Telegram answer
  - at least one FoodVisual is written after confirmation
- Evidence to record:
  - meal ID
  - Telegram prompt and answer, if any
  - created FoodItem names
  - FoodVisual count after completion

### Upload 2

- Action: send a different real meal photo
- Expectation:
  - the system still starts from learned data created during Upload 1 only
  - specific Indo-Pak naming is preserved where visible or user-confirmed
  - detector hints do not become the final persisted name if reasoning/interview provides a better name
- Evidence to record:
  - meal ID
  - any unresolved group labels shown in Telegram
  - new FoodItems/FoodVisuals created

### Upload 3

- Action: send either a repeated meal or a meal containing a repeated component from Upload 1 or 2
- Expectation:
  - repeated components begin matching learned visuals
  - fewer interview prompts are needed than on the first occurrence
  - if an interview still happens, it should be for a real unresolved detail rather than a generic label-first question
- Evidence to record:
  - repeated component name
  - whether interview was skipped, reduced, or still required
  - top observed outcome: vector match reuse, grouped reasoning reuse, or interview

### Upload 4 (only if Upload 3 does not yet prove reuse)

- Action: send one more natural meal with a repeated component
- Expectation:
  - by this point, at least one repeated component should show learned FoodVisual reuse
- Evidence to record:
  - repeated component name
  - whether the component skipped interview
  - final FoodItem/FoodVisual counts

## Pass Criteria

Mark this UAT complete only when all of these are true:

- [ ] DB was empty before Upload 1
- [ ] First confirmations created FoodItems and FoodVisuals from the empty state
- [ ] At least one naming decision is culturally specific enough for the actual meal, not just a generic curry/bread label
- [ ] Repeated meal or repeated component behavior is observed by Upload 3 or Upload 4
- [ ] Evidence shows the repeated component benefited from the newly learned FoodVisuals
