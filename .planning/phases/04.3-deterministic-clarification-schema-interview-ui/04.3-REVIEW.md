## Summary

Reviewed the Phase 04.3 gap-closure work after `2bea613`, with focus on plans `04.3-05` and `04.3-06`. The new per-group clarification contract is mostly wired through, but three shipped regressions remain in the interview/finalization path: source-origin answers can suppress grounding incorrectly, deterministic identity choices lose the selected candidate linkage before the final write, and the post-interview grounding worker can silently auto-confirm after provider failures instead of entering the new degraded-save/hold flow. The test suite passes, but one of the new worker tests models an exception shape that the production chat client does not actually raise.

## Critical Issues

### CR-01 [BLOCKER]: `SOURCE_ORIGIN` answers collapse `STORE_BOUGHT_PREPARED` and `UNKNOWN` into `HOME`, which skips required grounding

**File:** `app/services/interview_service.py:1651-1662`

**Issue:** `_source_type_from_choice()` maps every non-`PACKAGED_BRANDED` / non-`RESTAURANT` source-origin answer to `HOME`. That means the new five-state contract is immediately collapsed in the runtime: `STORE_BOUGHT_PREPARED` and `UNKNOWN` both become `HOME`. `_confirmation_items_from_clarification_answers()` then persists only that collapsed `source_type` (`app/services/interview_service.py:1822-1824`), and `final_resolution_from_confirmation()` decides whether to queue grounding from `build_grounding_prep()` (`app/services/interview_service.py:733-757`). Since grounding only runs for `PACKAGED` / `RESTAURANT`, a user selecting `store bought` or `not sure` can now be finalized as a verified home-cooked meal even though this action only exists for cases where source materially affects nutrition or grounding.

**Fix:**
```python
def _source_origin_state_from_choice(choice_id: str) -> str:
    normalized = str(choice_id or "").strip().upper()
    if normalized in {
        "HOME_COOKED",
        "STORE_BOUGHT_PREPARED",
        "PACKAGED_BRANDED",
        "RESTAURANT",
        "UNKNOWN",
    }:
        return normalized
    return "UNKNOWN"

# Persist the five-way source-origin state in answers/confirmation items,
# then map it to final source_type only in the authoritative resolver.
# Treat STORE_BOUGHT_PREPARED and UNKNOWN as grounding-required until resolved.
```

### CR-02 [BLOCKER]: deterministic identity choices drop the selected candidate linkage before the authoritative write

**File:** `app/services/interview_service.py:1721-1741`

**Issue:** When the user picks one of the ranked identity choices, `_answer_record_for_question()` stores only `choice_id`, `value`, and `name`; it never carries the selected candidate's `food_item_id` or any other stable food identity into the answer record. `_confirmation_items_from_clarification_answers()` then strips `choice_id` / `value` entirely from the confirmation payload (`app/services/interview_service.py:1772-1779`) and only keeps the display label as `name` (`app/services/interview_service.py:1830-1833`). `final_resolution_from_confirmation()` reads `food_item_id` only from the confirmation item, so the final write cannot reuse the intended FoodItem and falls back to name-based resolution instead. This is a regression from the reasoning auto-confirm path, which preserves `food_item_id` when building final segment resolutions.

**Fix:**
```python
# When building identity choices, carry candidate metadata through the prompt.
{
    "choice_id": candidate_id,
    "value": candidate_id,
    "label": label,
    "food_item_id": food_item_id,
}

# When the choice is selected, hydrate the answer/confirmation item with
# food_item_id and any authoritative candidate fields needed by finalization.
record["food_item_id"] = selected_choice.get("food_item_id")
```

### CR-03 [BLOCKER]: post-interview grounding provider failures are swallowed and turned into fallback auto-confirm writes

**File:** `app/services/reasoning_service.py:1519-1550`

**Issue:** `run_reasoning_request()` catches every exception from the grounding reasoning model, replaces it with a synthetic `FAILED_UNCLEAR` payload, and then immediately synthesizes fallback `food_groups` from the rebuilt match results. After `evaluate_reasoning_gate()`, that degraded payload can become `AUTO_CONFIRM` / `READY_TO_WRITE` again when the rebuilt candidates look strong enough. `poll_post_interview_grounding()` only enters `_apply_grounding_failure_policy()` when `_run_reasoning_pipeline()` raises (`bot/polling.py:944-954`), so real provider quota/auth/network failures can bypass the new `DEGRADED_SAVED` / `HOLD_REQUIRED` policy and finalize as if grounding had succeeded. I reproduced this locally by forcing `llm_client.chat_completion()` to raise; `run_reasoning_request()` still returned `AUTO_CONFIRM` / `READY_TO_WRITE`.

**Fix:**
```python
async def run_reasoning_request(..., propagate_errors: bool = False):
    try:
        parsed, trace_metadata = await _run_reasoning_model(...)
    except Exception:
        if propagate_errors:
            raise
        ...

# In poll_post_interview_grounding(), call with propagate_errors=True so
# quota/auth/network/tool failures reach _apply_grounding_failure_policy().
```

## Warnings

### WR-01 [WARNING]: the new grounding-failure classifier and test use the wrong exception surface for chat completions

**File:** `bot/polling.py:296-326`

**Issue:** `_classify_grounding_failure()` only recognizes `httpx.HTTPStatusError` and `httpx` transport exceptions. But the grounding chat path goes through `AsyncOpenAI.chat.completions.create()` (`app/services/llm_client.py:34-69`), which raises OpenAI SDK exceptions such as `RateLimitError`, `AuthenticationError`, and `APIConnectionError`, not `httpx.HTTPStatusError`. The new quota regression test also patches `run_reasoning_request()` to raise `httpx.HTTPStatusError` (`tests/test_match_flow.py:914-934`), so it does not cover the production exception types. Even after fixing CR-03, quota/auth failures from the real SDK would still be misclassified as generic tool failures.

**Fix:**
```python
from openai import APIConnectionError, APIStatusError, AuthenticationError, RateLimitError

if isinstance(error, RateLimitError):
    ...
elif isinstance(error, AuthenticationError):
    ...
elif isinstance(error, (APIConnectionError,)):
    ...
elif isinstance(error, APIStatusError):
    ...
```
