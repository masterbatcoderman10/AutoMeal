## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram update -> interview session | Untrusted callbacks and free text must map onto the pinned chat and exactly one open DB-owned session. |
| parser output -> FoodItem mutation | Free-text parsing can influence item identity and quantity and therefore must validate and confirm before write. |
| unresolved interview -> best-effort completion | The system may commit `is_verified=false`, but it must do so deliberately and never loop indefinitely. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-09 | Elevation of Privilege | `bot/handlers.py` | mitigate | Reject any callback or message not from the configured `TELEGRAM_CHAT_ID`, and resolve callback tokens against `InterviewSession` rows rather than trusting client payload state. |
| T-04-10 | Tampering | `app/services/interview_service.py` | mitigate | Advance only one targeted question at a time, persist each step to `InterviewSession`/`InterviewMessage`, and require final confirmation before `apply_final_meal_resolution()`. |
| T-04-11 | Repudiation | `tests/test_interview_flow.py` | mitigate | Assert the locked backbone, one-reminder rule, and `is_verified=false` best-effort closeout so interview behavior remains auditable. |
| T-04-12 | Information Disclosure | `app/services/grounding_stub.py` | mitigate | Store only minimal packaged/restaurant grounding-prep inputs and `NEEDS_GROUNDING` hints; do not run the full SearXNG or Firecrawl loop in Phase 4. |
| T-04-SC | Tampering | parser-model surface | mitigate | Use `google/gemini-3.1-flash-lite` first, fall back once to `google/gemini-3.5-flash`, and validate structured parser output locally before mutating state. |
</threat_model>
