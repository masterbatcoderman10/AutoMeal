## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram meal reply -> interview turn manager | Free-text user input becomes model context and must be treated as untrusted data, not as direct state mutation. |
| interview turn result -> finalization | Structured model output can advance the meal toward confirmation and therefore must not bypass validation or the authoritative writer. |
| kickoff prompt send -> durable transcript state | The bot-visible assistant prompt and the DB-owned prompt state must stay in sync so the next reply is interpreted against the same turn. |

## STRIDE Threat Register

| Threat ID | Category | Component | ASVS L1 Ref | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|----------|-------------|-----------------|
| T-04.2-05 | Tampering | `bot/handlers.py` | V5 Input Validation | High | mitigate | Replace `parse_interview_text()` for meal sessions with validated `run_interview_turn()` output so free text is interpreted in grouped context rather than isolated per-step parsing. |
| T-04.2-06 | Repudiation | `InterviewMessage` / `InterviewSession.current_prompt_payload` | V3 Session Management | Medium | mitigate | Persist every user and assistant turn durably, then rebuild turn context from the authoritative state plus the bounded transcript before each model call. |
| T-04.2-07 | Elevation of Privilege | `ready_to_confirm` path | V5 Input Validation | High | mitigate | Accept `ready_to_confirm` only after strict schema validation, full-group coverage checks, explicit `approval_status` coverage for every active clear and unclear group, and the one allowed repair retry; if output is still invalid or contradictory, send a neutral retry prompt and keep the session open instead of writing rows directly. |
| T-04.2-08 | Information Disclosure | model prompt composition | V4 Access Control | Medium | mitigate | Keep the turn payload to grouped reasoning context, prior transcript, and segment/crop references already owned by the meal; do not add Phase 5 tool results or invented nutrition facts. |
| T-04.2-SC | Tampering | package-manager surface | V5 Input Validation | Low | accept | No new packages or install tasks are allowed in this phase; orchestration must use the existing OpenRouter, Langfuse, and Pydantic stack. |

Security gate: per `.planning/config.json` (`security_asvs_level=1`, `security_block_on=high`), any unmitigated High finding blocks execution, finalization handoff, and downstream completion until fixed.
