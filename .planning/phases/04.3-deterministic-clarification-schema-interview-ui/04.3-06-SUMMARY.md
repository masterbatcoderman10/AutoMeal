**Deterministic Telegram clarification rendering with explicit affirmation correction steps and degraded post-grounding saves for confirmed meals**

## Accomplishments
- Replaced prompt synthesis from `question_focus` with direct rendering of reasoning-owned `clarification_actions[*].user_prompt` and stable question/group IDs.
- Changed affirmation handling so `No` inserts a same-group free-text correction question and persists the typed correction under `answers_by_question_id` without re-asking the original affirmation.
- Added explicit grounding failure classification and policy selection: confirmed meals now degrade-save as unverified with blocker metadata, and incomplete cases enter `HOLD_REQUIRED`.

## Decisions Made

- Affirmation questions are still asked after unresolved required clarifications when both exist, but once asked they are handled deterministically and never delegated back to the resolver for proof.
- Degraded saves reuse the authoritative final-write path with `best_effort` semantics while preserving FoodVisual creation when crop and embedding data already exist.
