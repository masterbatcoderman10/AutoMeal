## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runtime state -> Postgres | Phase 4 source of truth crosses from transient worker memory into durable interview, reasoning, correction, and recovery records. |
| quantity logic -> user-visible meal output | Rich quantity state must not collapse back into misleading bucket-only storage or fake precision. |
| tracing wrapper -> production workflow | Optional Langfuse telemetry must never become authoritative relative to DB state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `migrations/versions/002_phase4_state_surfaces.py` | mitigate | Add explicit JSON/enum/timestamp columns and new tables for reasoning, interview, correction, and recovery so later plans do not overload text blobs or PTB memory. |
| T-04-02 | Repudiation | `app/models/correction_event.py` | mitigate | Persist before/after JSON, trace id, visual-learning flags, and timestamps so `/fix` can prove exactly what changed and why. |
| T-04-03 | Information Disclosure | `config/reasoning_taxonomy.json` | mitigate | Keep only product taxonomy and quantity policy data in the file; do not store secrets or provider payloads in editable config. |
| T-04-04 | Denial of Service | `app/services/tracing_service.py` | mitigate | Make tracing a best-effort wrapper that returns `None` trace ids and swallows provider outages rather than blocking model calls. |
| T-04-SC | Tampering | Python dependency surface | mitigate | Add only `langfuse==4.7.0` from the approved package audit, keep it optional behind env toggles, and avoid any `[ASSUMED]` package installs. |
</threat_model>
