<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model draft -> service finalization | Model-authored food/nutrition facts become persisted verified data only after deterministic service checks |
| tool evidence -> source registry | Untrusted search/scrape content becomes source IDs and summaries for model selection |
| source selection -> provenance | Model-selected source IDs are resolved by the service into URLs, provenance, and trace state |
| output budget -> provider runtime | Finalizer output budget controls malformed response cost and truncation behavior |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-34 | Spoofing | finalizer response schema | mitigate | Remove `is_verified`, `provenance`, `source_url`, and trace fields from the model-facing schema. |
| T-05-35 | Tampering | citation/provenance fields | mitigate | Require selected source IDs that resolve to same-loop evidence before searched provenance can be persisted. |
| T-05-36 | Denial of Service | finalizer output budget | mitigate | Use a high finite output cap and reject malformed giant responses. |
| T-05-37 | Integrity | all-degraded finalization | mitigate | Fail closed instead of persisting completed empty nutrition rows. |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs are part of this gap-closure plan. |
</threat_model>
