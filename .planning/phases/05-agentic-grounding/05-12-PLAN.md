<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| finalizer outcomes -> reasoning save path | Model/tool degradation states become persisted meal status and diary rows. |
| finalization result -> Telegram reply | Backend write outcome crosses into user-facing success or blocker copy. |
| Telegram user reply -> interview state | User confirmation can deactivate an interview and commit final meal state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-38 | Tampering | `finalize_meal_from_reasoning()` | mitigate | Treat all-DEGRADED finalizer audit states as a FAILED terminal write with no final segments instead of trusting degraded fallback rows. |
| T-05-39 | Repudiation | `reasoning_state_json` | mitigate | Persist `ALL_FINALIZER_GROUPS_DEGRADED` and `grounding_failure.category=all_finalizer_groups_degraded` so the failed terminal state is auditable. |
| T-05-40 | Information Integrity | `bot/handlers.py` confirmation branches | mitigate | Gate success copy on non-empty meal_entries and non-FAILED meal status before deactivating the meal interview as successful. |
| T-05-41 | Spoofing | Telegram success message | mitigate | Use blocker/on-hold copy for failed or empty finalizations so the user is not told an unsafe save succeeded. |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs are part of this gap-closure plan. |
</threat_model>
