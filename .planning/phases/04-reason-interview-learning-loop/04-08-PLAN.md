## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scheduler tick -> recovery mutation | Background APScheduler work changes durable meal state without a direct user request. |
| persisted artifacts -> inferred reset stage | Recovery logic infers the correct last safe stage from crops, embeddings, candidates, and interview messages. |
| janitor failure -> user notification | Failure notices must be sent once and only after recovery is truly exhausted. |

## STRIDE Threat Register

High-severity gate: none in this plan. Every listed threat is medium or low severity and non-blocking once the listed mitigation is implemented.

| Threat ID | Category | Component | Severity | Blocking | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|----------|-------------|-----------------|
| T-04-17 | Denial of Service | `app/main.py` scheduler wiring | medium | no | mitigate | Register the janitor with `max_instances=1`, `coalesce=True`, and explicit stale/retry intervals so missed runs do not pile up. |
| T-04-18 | Tampering | `app/services/recovery_service.py` | medium | no | mitigate | Recover from the last safe artifact-backed stage instead of resetting blindly to `PENDING`, and exclude active interview states from machine-stage handling. |
| T-04-19 | Repudiation | `tests/test_janitor.py` | medium | no | mitigate | Assert the three-recovery ceiling, stale-stage exclusion list, and one-notification rule so recovery behavior is deterministic and auditable. |
| T-04-20 | Information Disclosure | `scripts/recovery_smoke.py` | low | no | mitigate | Report stage transitions and recovery outcome without printing raw provider responses, secrets, or full trace payloads. |
| T-04-SC | Denial of Service | duplicate prompt or write surface | medium | no | mitigate | Reuse stored stage metadata and sent flags, and never create a second final write or second failure notice for the same exhausted meal. |
</threat_model>
