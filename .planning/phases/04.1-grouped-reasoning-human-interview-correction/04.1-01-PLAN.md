## Phase Goal

**As a** MealTracker user, **I want to** have each distinct food in one meal reasoned about separately, **so that** chicken curry, egg curry, and pita are treated as separate decisions instead of competing whole-meal alternatives.

<objective>
Implement the grouped reasoning contract and grouped final-write adapter for Phase 04.1.

Purpose: This is the first corrective slice because the UAT failure is structural: the current root-level `top_3` lets unrelated foods compete, duplicates whole-meal candidates on every segment, and cannot safely auto-confirm grouped foods.
Output: grouped reasoning tests, strict grouped schema and gate logic, grouped meal/segment persistence, and one-logical-item-per-group auto-confirm writes.
Implements: D-01, D-02, D-03, D-04, D-05, D-06, D-16, D-17, D-18, D-19, D-20.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OpenRouter grouped output -> app gate | Model output crosses into durable routing logic and must not be trusted unless it satisfies the grouped schema and group-local gate rules. |
| grouped meal state -> segment audit rows | One meal-level reasoning result fans out into multiple segment audit rows and must preserve group ownership without duplicated whole-meal candidates. |
| grouped auto-confirm -> final DB write | Resolved food groups become diary and FoodVisual writes, so one grouped decision must not explode into duplicate final rows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.1-01 | Tampering | `app/services/reasoning_schema.py` | mitigate | Require `food_groups`, `group_id`, `segment_ids`, `primary_segment_id`, and exactly three candidates per group; keep strict structured outputs per D-02, D-03, and D-20. |
| T-04.1-02 | Tampering | `app/services/reasoning_service.py` | mitigate | Compute top-1/top-2 margin, gate reason, and meal aggregation inside each group only so unrelated foods never compete per D-04. |
| T-04.1-03 | Repudiation | `MealLog.reasoning_state_json` / `MealSegment.ai_reasoning` | mitigate | Persist the full grouped document once at meal level and write compact per-segment group references with `trace_id` and candidate IDs per D-05 and D-06. |
| T-04.1-04 | Tampering | `app/services/meal_resolution_service.py` | mitigate | Adapt grouped auto-confirm into one `FinalSegmentResolution` per logical food group using `primary_segment_id`, preventing duplicate diary writes while keeping the existing correction transaction authoritative. |
| T-04.1-SC | Tampering | package-manager surface | accept | No new packages or package-manager install tasks are allowed in this phase; dependency surface stays unchanged. |
</threat_model>
