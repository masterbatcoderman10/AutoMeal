## Phase Goal

**As a** MealTracker user, **I want to** have each accepted crop checked against my seeded visual library before any diary rows are created, **so that** unknown meals cleanly escalate to future reasoning instead of being falsely completed.

<objective>
Implement the all-or-nothing similarity gate for D-06, D-08, D-09, D-10, D-11, and D-12, with Phase 2 handoff corrected so `SEGMENTING` stops short of `COMPLETED`.

Purpose: Before successful match completion can exist, the runtime needs a trustworthy per-segment search path that can prove when a meal is not yet known and route it to `REASONING` without partial writes.
Output: an embed/search worker path, similarity threshold enforcement, and transparent unresolved-meal messaging.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| saved crop -> similarity query | Each persisted crop becomes an embedding query against the local visual corpus and must not silently widen to whole-meal matching. |
| pgvector distance -> application threshold | Database distance values cross into application business rules and must be converted correctly into similarity scores. |
| unresolved meal -> Telegram note | The bot must disclose unknown-meal status without leaking vector scores or internal debugging. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Tampering | `app/services/matching_service.py` | mitigate | Compute similarity as `1 - cosine_distance`, filter `is_invalidated=false`, and test the `0.85` threshold branch explicitly. |
| T-03-06 | Elevation of Privilege | `bot/polling.py` | mitigate | Keep the status-driven worker ownership model; only `SEGMENTING` can hand off to `EMBEDDING`, and only match workers can set `REASONING`. |
| T-03-07 | Information Disclosure | `bot/messages.py` | mitigate | Keep the unresolved Telegram note terse per D-11 and omit raw scores or debug fields per D-20. |
| T-03-08 | Repudiation | `tests/test_match_flow.py` | mitigate | Encode empty-index and below-threshold behavior as automated assertions so the unresolved branch is a planned result, not an operator guess. |
| T-03-SC | Tampering | Python dependency/runtime surface | accept | No new packages are installed in this plan; rely on the existing locked stack from Phase 1. |
</threat_model>
