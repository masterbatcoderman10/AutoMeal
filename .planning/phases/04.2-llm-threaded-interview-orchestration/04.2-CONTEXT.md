# Phase 04.2: LLM-Threaded Interview Orchestration

## Trigger

During live UAT, grouped reasoning improved enough to ask about the unresolved egg/vegetable curry detail. The user replied with a natural answer: `It's bottle gourd`.

The deterministic interview roadmap stored that literal answer as the food name, advanced to `FOOD_NAME`, and asked:

`What should I call It's bottle gourd?`

That proves the current interview continuation is not actually conversational. It is a local state machine that parses each reply in isolation.

## Gap

The interview needs an LLM turn manager, not only deterministic prompt templates.

Reasoning already knows:

- unresolved food groups
- clear/high-confidence food groups
- candidate choices
- missing evidence
- selected candidates / proposed final names
- segment IDs and labels
- gate reasons
- current question intent

The Telegram interview should thread that context into an interview LLM, include conversation history, and let the model decide whether to ask a follow-up, repair ambiguity, collect approval for clear items, or produce final structured confirmation items.

## Desired Flow

1. Reasoning produces unresolved grouped targets.
2. Interview session starts with a model-ready context object:
   - meal ID
   - unresolved groups
   - clear groups needing approval
   - candidate choices
   - missing evidence
   - proposed names for clear groups
   - current prompt
   - prior reasoning summary
   - segment/crop references where available
3. Each user reply is appended to durable `InterviewMessage` history.
4. The interview LLM receives:
   - system rules for concise food clarification
   - current structured interview state
   - prior assistant/user messages
   - latest user text
5. The model returns strict JSON:
   - `continue_interview`: ask another natural question
   - `need_clarification`: ask a targeted repair question
   - `ready_to_confirm`: return normalized confirmation items with approval/correction status for every group
6. On `ready_to_confirm`, the existing final write-back / post-interview grounding path remains authoritative.

## Non-Goals

- Do not add SearXNG/Firecrawl tool grounding here; that remains Phase 5.
- Do not replace the final write transaction.
- Do not expand nutrition derivation.
- Do not ask the model to invent missing nutrition facts.

## Acceptance Examples

- User answer `bottle gourd` to an egg/vegetable curry target resolves the item as `egg curry with bottle gourd` or a culturally appropriate equivalent, then moves to portion/source only if still needed.
- User answer `pita` to a bread target confirms the bread type without asking `What should I call pita?`.
- User answer `chicken leg` to a chicken curry target composes `chicken leg curry` and does not ask a duplicate naming question.
- If reasoning is already confident about `pita bread` and `chicken curry`, the interview prompt still includes them for approval, e.g. "I have pita bread and chicken curry; confirm or correct those while answering the egg curry detail."
- If multiple active interviews exist, a new reply is routed to the intended meal/thread and stale sessions cannot steal it.
