# Phase 04.2 UAT Checklist

## Scope

Use this checklist to prove the 04.2 interview slice works in the live bot:

- natural-answer composition for unresolved meal groups
- concurrent active interviews route to the intended prompt or fail closed
- clear approval candidate correction stays on the authoritative final write path
- Langfuse traces show the interview model, prompt context, and structured response

Do not expand this UAT into Phase 5 work:

- no SearXNG or Firecrawl validation
- no nutrition derivation changes
- no replacement of `finalize_confirmed_interview()` or `apply_final_meal_resolution()`

## Live Telegram Scenarios

Record the `meal_id`, the exact assistant question, the exact user reply, and the final Telegram outcome for each scenario.

### Scenario 1: `It's bottle gourd`

Goal:
- prove the interview composes a natural meal name instead of echoing the literal reply back as a new food name prompt

Steps:
1. Trigger a meal that reaches interview for an egg-and-vegetable curry style group.
2. Reply with `It's bottle gourd`.
3. Continue until the bot reaches confirmation or a short follow-up.

Pass if:
- the next assistant prompt is about the unresolved meal detail, not `What should I call It's bottle gourd?`
- the composed result is a natural meal name such as `egg curry with bottle gourd` or an equivalent culturally correct variant
- the final confirmation or save path still routes through the authoritative write-back

Evidence:
- `meal_id`
- assistant prompt before the reply
- assistant prompt after the reply
- final confirmation item name

### Scenario 2: two active meal interviews

Goal:
- prove one stale meal thread cannot steal a reply meant for another prompt

Steps:
1. Start two active meal interviews in the pinned Telegram chat and leave both open.
2. Reply directly to the older prompt message with a meal-specific answer.
3. Send one free-text message with no `reply_to_message` while both interviews are still active.

Pass if:
- the direct reply updates only the intended meal thread
- the unmatched free-text reply does not mutate either interview
- the bot responds with a short retry instruction telling you to reply to the specific meal prompt

Evidence:
- both `meal_id` values
- the `reply_to_message.message_id` used for the direct reply
- which interview advanced
- the exact ambiguous-reply retry text

### Scenario 3: clear approval candidate corrected in the same turn

Goal:
- prove a clear approval candidate can be corrected in the same turn without bypassing the authoritative writer

Steps:
1. Trigger a grouped meal where one item is already a clear approval candidate and one item still needs clarification.
2. In one answer, confirm the unresolved item and correct the clear approval candidate.
3. Let the meal finalize.

Pass if:
- the final confirmation items reflect the corrected name, not the original approval candidate
- the correction is visible in `confirmation_items`
- the write path still goes through `_finalize_interview_confirmation()` -> `finalize_confirmed_interview()` -> `apply_final_meal_resolution()`

Evidence:
- original approval candidate name
- corrected final name
- final Telegram confirmation or save message
- resulting `DiaryEntry` or `FoodVisual` row identifiers if you inspect the DB

## Langfuse Trace Inspection

Open the live interview trace for each scenario and confirm all of the following:

1. The trace model matches the interview model used for Phase 04.2.
2. The prompt context includes the current authoritative meal state, not just the last user text.
3. The trace shows the assistant prompt field as `assistant_prompt`.
4. The structured response shows the action and `confirmation_items` when the turn is ready to confirm.
5. The trace makes it clear which meal thread owned the turn.
6. The final authoritative write-back is visible through the downstream save path, not a second ad-hoc writer.

Minimum trace evidence to capture:

- `trace_id`
- `model`
- prompt context or serialized interview state
- `assistant_prompt`
- structured response payload
- `confirmation_items` when present
