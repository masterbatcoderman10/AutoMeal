## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user correction -> training data mutation | `/fix` can invalidate visuals and write new ones, so correction scope must be exact. |
| correction diff -> final mutation | The preview shown to the user must match the actual DB side effects. |
| quantity-only edit -> diary recompute | Quantity changes affect nutrition but must not alter visual identity state. |

## STRIDE Threat Register

High-severity gate: none in this plan. Every listed threat is medium or low severity and non-blocking once the listed mitigation is implemented.

| Threat ID | Category | Component | Severity | Blocking | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|----------|-------------|-----------------|
| T-04-13 | Tampering | `app/services/correction_service.py` | medium | no | mitigate | Separate identity changes from quantity/detail changes and invalidate only the linked `FoodVisual` for confirmed identity corrections. |
| T-04-14 | Repudiation | `app/models/correction_event.py` | medium | no | mitigate | Append a correction event with before/after JSON, trace ID, visual-learning flag, and timestamps instead of overwriting history. |
| T-04-15 | Elevation of Privilege | `bot/handlers.py` | medium | no | mitigate | Resolve `/fix` targets server-side from `DiaryEntry` IDs or recent-entry query results rather than trusting client-submitted correction state. |
| T-04-16 | Information Disclosure | `bot/messages.py` | low | no | mitigate | Show side-effect diffs and updated summaries without leaking hidden reasoning traces or raw model internals. |
| T-04-SC | Tampering | corrected visual write-back | medium | no | mitigate | Gate new visual creation on `visual_learning_eligible` and do not append a corrected visual for quantity-only or visually useless changes. |
</threat_model>
