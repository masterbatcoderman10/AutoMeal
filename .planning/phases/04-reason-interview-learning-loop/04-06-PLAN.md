## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram update -> interview session | Untrusted callbacks and free text must map onto the pinned chat and exactly one open DB-owned session. |
| parser output -> FoodItem mutation | Free-text parsing can influence item identity and quantity and therefore must validate and confirm before write. |
| unresolved interview -> best-effort completion | The system may commit `is_verified=false`, but it must do so deliberately and never loop indefinitely. |

## STRIDE Threat Register

High-severity gate: none in this plan. Every listed threat is medium or low severity and non-blocking once the listed mitigation is implemented.

| Threat ID | Category | Component | Severity | Blocking | Disposition | Mitigation Plan |

| T-04-09 | Elevation of Privilege | `bot/handlers.py` | medium | no | mitigate | Reject any callback or message not from the configured `TELEGRAM_CHAT_ID`, and resolve callback tokens against `InterviewSession` rows rather than trusting client payload state. |

| T-04-11 | Repudiation | `tests/test_interview_flow.py` | medium | no | mitigate | Assert the locked backbone, D-48 and D-49 edit branches, the one-reminder rule, and `is_verified=false` best-effort closeout so interview behavior remains auditable. |
