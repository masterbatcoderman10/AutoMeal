# 04.3 UAT Harness Checklist

This runbook closes GAP-04.3-P3 only. Use the repo-owned 04.3 harness to clone the warm checkpoint from D-18, ingest the named regression samples through the normal local API path, and capture the D-19/D-20 evidence in one JSON report.

## Scope

- **D-18:** Preserve `mealttracker_uat_with_meal_embeddings` and clone it only into a disposable warm harness database.
- **D-19:** For each named regression sample, stop when the meal reaches `INTERVIEWING`, `RETRY_PENDING`, `GROUNDING_PENDING`, or `COMPLETED`, then record prompts, answers, `DiaryEntry` rows, `FoodVisual` rows, and grounding status.
- **D-20:** Record trace IDs plus serialized reasoning, interview, and resolver state from the harness report.

This checklist does **not** re-open the already-fixed 04.3 approval or grounding logic. It only tells the operator how to run the harness and what evidence to copy into `04.3-UAT-RESULTS.md`.

## Files Used

- Harness script: `scripts/embed_match_smoke.py`
- Compose override: `docker-compose.uat-043-harness.yml`
- Warm checkpoint: `mealttracker_uat_with_meal_embeddings`
- Disposable target database: `mealttracker_043_harness`
- Report directory: `uploads/reports/04.3/`

- Docker services are available locally.

## 4. Report Location And Expected Shape

Each run writes a JSON report to:

- `uploads/reports/04.3/partial-match-<meal-id>.json`
- `uploads/reports/04.3/no-match-<meal-id>.json`

The report must contain these top-level sections:

- `scenario`
- `database`
- `api`
- `meal`
- `reasoning`
- `interview`
- `diary_entries`
- `food_visuals`
- `grounding`
- `traces`

Important evidence fields to inspect:

- `meal.id`
- `meal.status`
- `reasoning.clarification_schema`
- `reasoning.answers_by_question_id`
- `reasoning.resolver_payload`
- `interview.state_key`
- `interview.current_prompt`
- `interview.messages`
- `diary_entries`
- `food_visuals`
- `grounding.roadmap_step`
- `grounding.status`
- `traces.ids`

The harness report is intentionally limited to application state, row snapshots, and trace identifiers. It must not contain auth headers, provider keys, or other secrets.

## 5. How To Interpret Outcomes

The harness stops as soon as the meal reaches one of these states:

- `INTERVIEWING`
  - Expected when clarification has started and the report should show the current question plus any recorded answers.
- `RETRY_PENDING`
  - Expected when grounding handoff or follow-up work is queued for retry; copy the reported grounding state and trace IDs as evidence.
- `GROUNDING_PENDING`
  - Expected when the deterministic interview is done and the meal is waiting on post-interview grounding; copy the current grounding status and any resolver payload.
- `COMPLETED`
  - Expected when final save finished; copy the final `DiaryEntry` rows, `FoodVisual` rows, and trace IDs.

These are observation states, not operator prompts. Do not manually edit the database or send ad-hoc Telegram messages as part of GAP-04.3-P3 verification.

- `reasoning.clarification_schema`

- `grounding.roadmap_step`
