**Source:** `bot/handlers.py:116-141`  
Apply to all Telegram entry points in Phase 4.2.
- Always call `_reject_unpinned_update` before processing.
- Resolve session with chat-scoped query.

### Structured output and strict schema contracts
**Source:** `app/services/reasoning_schema.py` + `app/services/reasoning_service.py` + `app/services/llm_client.py`  
Apply to new interview turn models.
- use `response_format` with `type: json_schema`, `strict: True`, and `additionalProperties: False`.
- keep `max_tokens` explicit and bounded.

### Fallback and repair loops
**Source:** `app/services/reasoning_service.py:785-847`  
Apply to new interview turn manager with model fallback list and parser repair list.

### Durable state + transcript as single source of truth
**Source:** `app/services/interview_service.py:509-546`, `app/services/interview_service.py:370-431`  
Apply to 04.2 reply flow:
- append each user/bot turn to `InterviewMessage`.
- store authoritative interview state in `InterviewSession.current_prompt_payload`.

All `ready_to_confirm` outputs must be shaped into `confirmation_items` and must pass through `finalize_confirmed_interview()` + `apply_final_meal_resolution()` unchanged in ownership.
