# Phase 04.3 - Security

Retroactive security verification for the deterministic clarification schema and interview UI phase.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OpenRouter reasoning output -> normalized grouped reasoning state | Untrusted model JSON crosses into app state and must be normalized before gating, persistence, or Telegram rendering. |
| normalized/grouped reasoning state -> clarification renderer | Group-owned candidates, action ordering, and prompt metadata become user-facing questions. |
| persisted clarification state -> Telegram prompt | Stored question metadata is reused across retries and restarts. |
| Telegram callback/text reply -> stored answer state | User input must map back to persisted question identity before state mutation. |
| completed clarification state -> resolver input | Final resolver execution must be blocked until required clarification is complete. |
| resolver/finalization output -> authoritative DB write path | Final write behavior must stay inside the shared meal-resolution path, including degraded grounding outcomes. |
| local UAT harness -> checkpoint clone/reset + evidence report | Harness automation must avoid destructive production targets and must emit auditable, redacted reports. |
