## Retail Source Semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Collapse retail branches | Treat all non-home retail food as one store-bought/packaged bucket. | |
| Keep packaged vs prepared distinct | Preserve `PACKAGED_BRANDED` and `STORE_BOUGHT_PREPARED` as different downstream states. | ✓ |
| Restaurant-only branching | Distinguish restaurant from home, but keep all retail food together. | |

**User's choice:** Keep packaged/branded and store-bought prepared distinct.
**Notes:** User example: khubz from a brand like Al Khayam is packaged/branded, while ID parottas are prepared. The store-bought branch should still be able to collect brand, and restaurant keeps its own name follow-up.

## Learned Source Consensus

| Option | Description | Selected |
|--------|-------------|----------|
| Always ask generic source | After identity is chosen, always ask the standard source question. | |
| Ask source-consensus affirmation | If learned history for the chosen identity strongly favors one source, ask an affirmation such as "most readings so far have been home, agreed?" | ✓ |
| Jump straight to learned values list | After identity, present historical source values as the next choice list instead of affirmation. | |

**User's choice:** Use a learned source-consensus affirmation when the learned source pattern is strong enough.
**Notes:** Example: if many strong rice embeddings have all been home so far, skip the generic source question and ask for agreement with the dominant source instead. If there is no compatible or strong source distribution for the selected identity, fall back to the generic source question.

## Failed Affirmation Handling

| Option | Description | Selected |
|--------|-------------|----------|
| Re-open fixed choices | Rejecting an affirmation sends the user back to another deterministic choice list. | |
| Free-text correction | Rejecting an affirmation immediately asks the user to type the correct answer and passes that into post-processing. | ✓ |
| Mark unresolved | Rejecting an affirmation stops the flow and leaves the group unclear. | |

**User's choice:** Use a free-text correction path.
**Notes:** This applies to the new source-consensus affirmation case too, not only identity affirmations. The typed answer should be accepted and passed forward to the existing post-processing/finalization path.
